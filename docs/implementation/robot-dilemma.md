# Реализованный сценарий: «Сломанный робот»

В списке доступны восемнадцать исполняемых сценариев на общей механике выбора: исходный
«Сломанный робот» и ещё семь заданий из первых трёх глав спецификации. Порядок
прохождения пока не вводится: каждое задание доступно при положительной сытости и наличии жетона.

## Разделение ответственности

- `features/tasks/DilemmaCatalog.kt` — контент и последствия вариантов всех восемнадцати заданий.
- `features/tasks/LevelTaskCatalog.kt` — соответствие между узлами карты уровней и заданиями.
- `DilemmaRenderer` — общий Compose-шаблон выбора. Он намеренно используется для
  этого небольшого набора; отдельные визуальные механики витрины, сортировки и конвертов
  остаются следующей самостоятельной частью движка.
- `TaskRunnerViewModel` — состояние, подтверждение и отображение сохранённого результата.
- `DilemmaRules.kt` — чистая проверка доступности и расхода одного жетона.
- `TasksRepository` — одна Room-транзакция для баланса, питомца и результата.

## Принятые правила

Ремонт списывает 20 монет именно из копилки, сбрасывает её серию дней без снятий
и оставляет Финни спокойным. Отложенный ремонт бесплатен, сохраняет копилку
и радует Финни. Оба решения дают объяснение и награду 20 монет в кошелёк.
Автоматического перевода награды в копилку нет: накопления остаются решением игрока.
Перед применением любого решения показывается подтверждение с последствиями;
для ремонта дополнительно объясняется отдаление цели и сброс серии.

Подтверждение атомарно сохраняет результат и расходует ровно один жетон.
Закрытие до подтверждения ничего не меняет. Повторное открытие показывает
сохранённый результат; повторная отправка, включая конкурентную, возвращает
его без повторных начислений. Закрытие приложения после подтверждения не теряет результат.
После последнего жетона наступает `Night`; экран итогов дня не входит в этот этап.

Room обновлён с версии 1 до 2 автоматической миграцией, добавляющей таблицу
`task_completion` без удаления старых данных. Сброс игры очищает и результаты заданий.

## Проверка

`./gradlew :shared:jvmTest` проверяет правила, нехватку накоплений,
конкурентные отправки, повторное открытие базы, миграцию версии 1 и откат при ошибке записи.
В общем DI-модуле явно подключён `BundledSQLiteDriver`, необходимый для открытия Room.
Android: `./gradlew :androidApp:assembleDebug`.
Для ручной проверки: «Задачи» → «Сломанный робот» → выбор → подтверждение →
«В комнату» → повторное открытие; проверить прежний результат и неизменность баланса.

На Windows проверка выполнена с кэшем Gradle в `.gradle/verification-home` на диске D:
это устранило ошибку запуска тестового процесса с кириллицей в пути и нехватку места
для сборки в исходном кэше. Все 14 JVM-тестов прошли.

## Мини-игра «Тетрис»

После прохождения уровня 10 на главном экране появляется фиолетовая иконка «ТЕТРИС».
Цель игры —
очистить 10 линий; за победу начисляются 3 монеты. Управление: влево, вправо,
поворот и мгновенное падение фигуры. Награда выдаётся один раз за каждую победу.
Debug APK успешно собран: `androidApp/build/outputs/apk/debug/androidApp-debug.apk`.
Ручная проверка интерфейса на устройстве в рамках этой реализации не выполнялась.
